## 一分钟上手

1. 在 `posts/` 里复制 `_模板.md`，改名成 `2026-10-22-wo-de-ri-ji.md`
2. 改开头的标题和日期，下面写正文
3. 双击 **`发布.cmd`**，等 1～2 分钟，刷新网址

想先看效果就双击 **`预览.cmd`**（浏览器打开 `http://localhost:4000`），看完关掉黑窗口。

## 文件夹里有什么

```
blog/
├── site.config.json   站点的所有设置（站名、导航、首页文案……）
├── posts/             随笔 —— 你自己写的
├── archive/           存档 —— 你收藏的别人的文章
├── pages/about.md     「关于我」页面
├── assets/
│   ├── styles.css     样式（颜色、字号都在这里）
│   ├── app.js         深浅色切换 + 搜索
│   └── img/           放照片
├── src/               生成器源码（一般不用动）
├── dist/              自动生成的网页，不用管，可以删
├── serve.mjs          本地预览服务
├── 预览.cmd           看效果
└── 发布.cmd           上线
```

### 三条铁律

| 只改这些 | 说明 |
| --- | --- |
| `posts/` `archive/` `pages/` | 内容 |
| `site.config.json` | 站点设置 |
| `assets/img/` `assets/styles.css` | 图片和外观 |

**不要改 `dist/`**：每次发布都会整份重新生成，改了会被覆盖。
**不要在 GitHub 网页上直接改文件**：本地发布是一份完整快照，会覆盖掉网页上的改动。
**不要用中文或空格命名 `.md` 文件**：文件名会变成网址。

## 写一篇随笔

文件放在 `posts/`，内容像这样：

```markdown
---
title: 今天下了一场雨
date: 2026-10-22 20:30
tags: [日常, 成都]
summary: 一句话摘要，会出现在列表和搜索结果里。
---

正文从这里开始。空一行就是新的一段。

## 小标题

> 引用会被排成左边有一条竖线的样子。

普通段落。
```

- 两个 `---` 之间是**配置**，下面是**正文**
- 只有 `title` 和 `date` 建议写，其余都可以省
- `posts/_模板.md` 是现成模板，复制改名即可（文件名以 `_` 开头的不会被发布）

发布后网址是 `https://qciao.github.io/posts/wo-de-ri-ji/`（取文件名里日期后面的部分）。

## 收藏一篇文章

文件放在 `archive/`：

```markdown
---
title: 论闲散
author: 伯特兰·罗素
source: https://原文链接
date: 2026-10-20
tags: [哲学, 长文]
summary: 为什么想留着它（可选）
---

（可选）摘录几段，或者写几句自己的想法。
```

- 出现在「存档」板块，不进 RSS
- **不写正文也可以**，只留标题、作者、链接，就是一条"我读过，值得留着"的记录
- 详情页会自动显示 `原文：example.com ↗`
- `archive/_模板.md` 也是现成模板

## 文件名与日期的规矩

| 文件名 | 网址 | 说明 |
| --- | --- | --- |
| `2026-10-22-wo-de-ri-ji.md` | `/posts/wo-de-ri-ji/` | 推荐写法 |
| `2026-10-22.md` | `/posts/2026-10-22/` | 也可以，但网址不直观 |
| `_模板.md` | 不发布 | 下划线开头一律跳过 |

**日期取值顺序**：开头写的 `date` → 文件名里的日期 → 文件的修改时间。

日期格式两种都行：`2026-10-22` 或 `2026-10-22 20:30`（后者用于同一天多篇时排序）。

## 所有可以写的字段

### 随笔（posts/）

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `title` | 建议 | 标题 |
| `date` | 建议 | 日期，决定排序和热力图 |
| `tags` | 否 | `[日常, 读书]` 或 `日常, 读书` 都行 |
| `summary` | 否 | 列表和搜索里的摘要，不写就自动截取正文开头 |
| `draft` | 否 | `draft: true` 表示草稿，不发布 |

### 存档（archive/）

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `title` | 是 | 文章标题 |
| `author` | 建议 | 作者，显示在列表右侧和详情页 |
| `source` | 建议 | 原文链接 |
| `date` | 建议 | 收藏日期 |
| `tags` | 否 | 和随笔共用一套标签 |
| `summary` | 否 | 一句话说明 |
| `draft` | 否 | 同上 |

> 阅读时长是按每分钟 300 字自动估的，不用手写。

## Markdown 语法

```markdown
## 小标题（`#` 会自动降一级，给文章标题让路）
### 更小的标题

**加粗**　*斜体*　~~删除线~~　==高亮==

> 引用

- 无序列表
- 第二项
  - 缩进两格是子项

1. 有序列表
2. 第二项

- [ ] 没做完的事
- [x] 做完的事

[链接文字](https://example.com)

![图注](../assets/img/x.jpg "图注会显示在照片下面")

| 表头 | 表头 |
| --- | --- |
| 内容 | 内容 |

---
```

代码块用三个反引号包起来：

````markdown
```js
console.log('hello')
```
````

> 原始 HTML 标签会被转义成普通文字显示，不会生效（这是有意的，安全）。

## 放照片

1. 把图片拖进 `assets/img/`，例如 `assets/img/20261022.jpg`
2. 正文里写：

```markdown
![雨后的窗台](/assets/img/20261022.jpg "雨后的窗台")
```

3. 发布后地址是 `https://qciao.github.io/assets/img/20261022.jpg`

- 路径必须写 `/assets/img/文件名`，**大小写要一致**
- 建议压到 300KB 以内（手机拍的原图通常 3MB+，会让页面很慢）
- 支持 jpg / png / webp / gif

## 预览与发布

| 做什么 | 怎么做 | 背后发生了什么 |
| --- | --- | --- |
| 看效果 | 双击 `预览.cmd` | 生成 `dist/`，起一个本地服务器，打开 `http://localhost:4000` |
| 上线 | 双击 `发布.cmd` | 生成 `dist/`，把网页和源码一起提交到 GitHub，Pages 自动重建 |

习惯命令行的话：

```bash
node src/build.mjs           # 只生成
node src/build.mjs --drafts  # 连草稿一起生成，用于预览
node src/publish.mjs         # 生成并发布
```

发布完成后：

- 等 30 秒～2 分钟才能在线上看到
- 看不到就按 `Ctrl + F5` 强制刷新

**发布是怎么实现的**：走 GitHub API（不需要装 git），用的是本机 `gh` 的登录状态。
仓库 `qCiao/qCiao.github.io` 的根目录是生成的网页，`source/` 是你的源码。

## 改站点的样子

### 站名、标语、首页文案

全部在 **`site.config.json`**，改完保存（UTF-8），再发布：

| 字段 | 显示在哪 |
| --- | --- |
| `title` | 站名（左上角大字、浏览器标签） |
| `tagline` | 站名下面那行小字 |
| `author` | 页脚署名 |
| `description` | 搜索引擎和分享卡片上的描述 |
| `url` | 站点地址（换域名时改） |
| `perPage` | 最近文章每页几篇（默认 8） |
| `hero.kicker` | 首页最上面那行小字 |
| `hero.lead` | 首页那句话（26px 大字） |
| `hero.note` | 首页那段说明 |
| `now` | 首页「近来」三行：在做 / 在想 / 在读 |
| `nav` | 顶部导航（label 文字 + href 链接） |
| `sidebar.position` | 侧栏在左还是右：`"left"` 或 `"right"`（默认右） |
| `sidebar.avatar` | 侧栏圆形头像的图片路径，例如 `/assets/img/avatar.jpg`（删掉这行就不显示头像） |
| `sidebar.about` | 侧栏「关于」那段话 |
| `sidebar.tagLimit` | 侧栏显示几个标签 |
| `footer` | 页脚版权说明 |

「关于我」页面的正文在 `pages/about.md`，直接改文件。

### 头像

侧栏左上角那个圆形头像就是 `assets/img/avatar.jpg`。

- 换头像：直接用新图**覆盖**这个文件（正方形、300×300 以上最好，压缩到 200KB 以内）
- 圆形是样式裁的，原图不用自己剪圆，但靠边的内容会被裁掉一点，**把脸放在正中间**就没问题
- 不想显示头像：把 `site.config.json` 里 `sidebar.avatar` 这一行删掉

### 颜色、字体、字号

都集中在 `assets/styles.css` 最上面：

```css
:root {
  --paper: #fbf9f4;   /* 纸张底色 */
  --ink:   #1b1a17;   /* 正文颜色 */
  --ink-2: #35322c;   /* 次级文字 */
  --muted: #6a645b;   /* 日期、说明等小字 */
  --accent:#2c4557;   /* 强调色：日期、链接、小节前的短线 */
  --wrap: 1150px;     /* 版心宽度 */
  --side: 236px;      /* 右侧栏宽度 */
}
```

深色模式在下面这一段，改同样的几个变量即可：

```css
html[data-theme="dark"] { ... }
```

想调正文大小，找 `.post-body` 里的 `font-size: 18px`；列表标题在 `.entry-title` 的 `font-size`。

### 字体

```css
--serif: Georgia, "Songti SC", "Source Han Serif SC", "Noto Serif SC", SimSun, serif;
--sans:  -apple-system, "PingFang SC", "Microsoft YaHei", ...;
```

前面是西文，后面是中文。装了「思源宋体 / 更纱宋体」的话，把它的名字加到前面，中文会更好看。

## 标签、搜索、RSS、热力图

这四样都是**自动**的，不需要维护：

| 功能 | 怎么来的 |
| --- | --- |
| 标签页 | 扫所有文章的 `tags`，自动生成 `/tags/日常/` 这类页面 |
| 站内搜索 | 生成 `index.json`，`/search/` 页面在前端搜索，支持按 `/` 聚焦 |
| RSS | `feed.xml`，只包含随笔 |
| 写作记录 | 页面最底部的方格图，按周统计随笔篇数，灰阶五档 |

- 删掉某个标签：把文章里的这个词去掉，重建后标签页自动消失
- 想换标签名：全文替换那个词，重建即可（旧网址会失效）
- 热力图鼠标悬停能看到「几月几日–几月几日 · N 篇」

## 常见问题

**改完发布，线上还是旧的？**
先等 1～2 分钟，再 `Ctrl + F5`。GitHub Pages 的 CDN 有缓存，通常几十秒。

**双击 `发布.cmd` 报错？**
- 提示 `authentication` / `找不到 GitHub 登录信息` → 在 PowerShell 里运行 `gh auth login`
- 提示 JSON 报错 → `site.config.json` 被改坏了，看它说的行号，多半是少了引号或逗号

**图片显示不出来？**
1. 文件真的在 `assets/img/` 里吗？
2. 路径是不是 `/assets/img/文件名.jpg`？
3. 大小写、后缀名是否一致（`.jpg` 不等于 `.JPG`）

**文件名用了中文怎么办？**
能发布，但网址会变成 `%E4%B8%AD%E6%96%87` 这样一长串。建议改成拼音。

**想暂时不发布某篇？**
开头加一行 `draft: true`。预览时想看草稿：`node src/build.mjs --drafts`。

**一篇文章的排序不对？**
按 `date` 倒序排。检查开头写的时间，或文件名里的日期。

**怎么删一篇文章？**
删掉 `posts/` 里那个 `.md`，再发布。旧网址会变成 404，这是正常的。

**能在手机上写吗？**
先在备忘录写，回电脑再贴进 `.md`。直接在 GitHub 网页上改的内容，下次发布会覆盖。

**能换自己的域名吗？**
1. 域名商加 CNAME 记录，指向 `qciao.github.io`
2. 仓库 Settings → Pages → Custom domain 填域名
3. 等证书签发后勾上 Enforce HTTPS
4. 把 `site.config.json` 的 `url` 改成新域名，再发布

## 备份、恢复、换电脑

- **整个 `blog` 文件夹就是全部底稿**，复制到 U 盘/网盘就是一份备份
- 线上仓库的 `source/` 也存着完整源码，随时能下载回来
- 每次发布都是一次 Git 提交，写坏了可以在 GitHub 的提交记录里翻旧版本、把内容拷回来
- 换电脑：拷文件夹 → 装 Node.js → `gh auth login` → 照常双击 `发布.cmd`
