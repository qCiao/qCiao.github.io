# qCiao · 个人博客

线上地址：**https://qciao.github.io/**

一个只写日记的静态博客。没有数据库、没有后台、没有第三方脚本：你在 Markdown 文件里写字，一条命令生成整站，推到 GitHub Pages 就是线上版。

站上只有三个板块：

| 板块 | 放什么 | 文件在哪 |
| --- | --- | --- |
| **最近文章** | 你自己写的随笔、日记 | `posts/` |
| **存档** | 你收藏的别人的文章（标题、作者、原文链接，可带摘录） | `archive/` |
| **关于我** | 一段自我介绍 | `pages/about.md` |

标签是通用的：随笔和存档都能打标签，标签页会把两类内容分开列出。

---

## 三步发一篇新文章

1. **新建文件**：在 `posts/` 里复制一份 `_模板.md`，把文件名改成 `2026-10-22-英文短名.md`
2. **写内容**：改掉开头 `---` 之间的标题、日期、标签，然后在下面写正文
3. **双击 `发布.cmd`**：等 1～2 分钟，打开 https://qciao.github.io/ 就能看到

想先看效果，就双击 `预览.cmd`（浏览器会打开 `http://localhost:4000`），看完关掉窗口即可。
发布和预览都会自动重新生成全站，不需要你手动处理任何 HTML 文件。

> **两条规矩**
>
> 1. 只改 `posts/`、`archive/`、`pages/`、`site.config.json`、`assets/img/`。
>    `dist/` 是自动生成的，改了会被覆盖；**千万不要在 GitHub 网页上直接改文件**，下次发布会被本地这份覆盖掉。
> 2. 文件名后半段用英文或拼音（它会变成网址），别用中文，也别用空格。

## 二、写一篇随笔

1. 在 `posts/` 里新建一个 `.md` 文件，命名格式：`年-月-日-英文短名.md`
   例如 `2026-10-21-chi-fan.md`
2. 开头写这段（两个 `---` 之间是配置，下面是正文）：

```markdown
---
title: 今天吃了一顿很慢的饭
date: 2026-10-21 20:30
tags: [日常, 成都]
summary: 一句话摘要，会出现在列表和搜索结果里。
---

正文从这里开始。空一行就是新的一段。

## 小标题

> 引用会被排成左边有一条竖线的样子。
```

3. 双击 `预览.cmd` 看看，满意了就双击 `发布.cmd`。

`posts/_模板.md` 是现成的模板，复制一份、改个名字就能开始写。**文件名以 `_` 开头的文件不会被发布。**

### 随笔可以写的字段

| 字段 | 是否必填 | 说明 |
| --- | --- | --- |
| `title` | 建议写 | 文章标题 |
| `date` | 建议写 | `2026-10-21` 或 `2026-10-21 20:30`，不写就用文件名里的日期 |
| `tags` | 可选 | `[日常, 读书]`，也可以写成 `日常, 读书` |
| `summary` | 可选 | 列表页和 RSS 里显示的摘要；不写就自动截取正文开头 |
| `draft: true` | 可选 | 加了这句，暂时不发布 |

文件名里的英文短名会变成网址：`2026-10-21-chi-fan.md` → `/posts/chi-fan/`。

## 三、收藏一篇文章

存档里的每一条，都是一个 `.md` 文件，放在 `archive/` 里：

```markdown
---
title: 论闲散
author: 伯特兰·罗素
source: https://原文链接
date: 2026-10-20
tags: [哲学, 长文]
summary: 为什么想留着它（可选）
---

（可选）摘录几段，或者写几句自己的想法。

也可以什么都不写，只留标题、作者和原文链接。
```

| 字段 | 是否必填 | 说明 |
| --- | --- | --- |
| `title` | 必填 | 文章标题 |
| `author` | 建议写 | 作者，会显示在列表右侧和详情页上 |
| `source` | 建议写 | 原文链接，详情页会显示成 `原文：example.com ↗` |
| `date` | 建议写 | 你收藏它的日期 |
| `tags` | 可选 | 和随笔共用一套标签 |
| `summary` | 可选 | 列表和搜索里的一句话说明 |

`archive/_模板.md` 也是现成的，复制改名即可。
不写正文也完全没问题——它就是一条「我读过这个，值得留着」的记录。

## 四、改站点信息

所有"关于这个站"的设置都在 **`site.config.json`**，改完重新发布即可：

| 字段 | 作用 |
| --- | --- |
| `title` | 站名（左上角的大字） |
| `tagline` | 站名下面那行小字 |
| `author` | 页脚署名 |
| `description` | 搜索引荐和分享卡片上的描述 |
| `url` | 站点地址，绑了自定义域名时记得改 |
| `hero` | 首页开场：`kicker`（上面的小字）、`lead`（那句大字）、`note`（下面一段） |
| `now` | 首页"近来"三行：在做 / 在想 / 在读 |
| `nav` | 顶部导航（默认：最近文章 / 存档 / 标签 / 关于我） |
| `sidebar.about` | 右侧栏"关于"那段话 |
| `perPage` | 最近文章每页几篇 |
| `footer` | 页脚那句版权说明 |

保存时请选 **UTF-8** 编码。自我介绍单独放在 `pages/about.md`。

## 六、发布是怎么工作的

GitHub 仓库 **[qCiao/qCiao.github.io](https://github.com/qCiao/qCiao.github.io)** 里：

- **根目录**：生成好的网页（`index.html`、`blog/`、`archive/`、`assets/`……），Pages 直接托管这里
- **`source/`**：源码（Markdown、配置、样式、脚本），也就是你这台电脑上的这份

`发布.cmd` 会自动做完：生成 → 把「网页 + 源码」一次性提交到 `main`。
它走的是 GitHub API，用的是你本机 `gh` 的登录状态，**不需要装 git，也不会弹窗要密码**。

如果发布后刷新看不到变化：等一分钟再强刷（Ctrl+F5），GitHub 有时会慢几十秒。

### 换电脑 / 备份

- 这个 `blog` 文件夹就是你的全部底稿，**拷到哪台电脑都能用**（装 Node.js、`gh auth login` 一下就能发布）
- 线上仓库里的 `source/` 也存着一份完整源码，随时可以下载回来
- 每次发布都是一次提交，写坏了可以在 GitHub 的提交记录里翻回旧版本
- 想更保险，可以定期把整个文件夹复制一份到 U 盘或网盘

## 八、放照片

1. 把图片放进 `assets/img/`，例如 `assets/img/20261021.jpg`
2. 正文里写：`![雨后的窗台](/assets/img/20261021.jpg "可选的图注")`
3. 发布后图片地址就是 `https://qciao.github.io/assets/img/20261021.jpg`

图片建议压到 300KB 以内，否则打开会慢。

## 九、换成自己的域名（可选）

1. 域名商后台加一条 CNAME：主机记录填 `www`（或 `blog`），指向 `qciao.github.io`
2. 仓库 Settings → Pages → Custom domain 填你的域名，保存
3. 等证书签发（几分钟到几小时），勾上 Enforce HTTPS
4. 把 `site.config.json` 里的 `url` 改成新域名，再发布一次

## 十、常见问题

**双击 `预览.cmd` 窗口一闪就没了？**
说明 Node 报错了。在这个文件夹里手动打开 PowerShell，运行 `node src/build.mjs`，看红字提示。

**发布失败，提示 authentication？**
在 PowerShell 里运行 `gh auth login` 重新登录，再发布。

**想改颜色 / 字号 / 版心宽度？**
都在 `assets/styles.css` 最上面那段 `:root` 变量里：`--paper` 纸张底色、`--ink` 字色、`--accent` 强调色、`--wrap` 版心宽度。

**存档和随笔的区别是什么？**
随笔是你写的（`posts/`，出现在「最近文章」），存档是别人写的、你想留着的（`archive/`，出现在「存档」）。两者共用标签和搜索。

**页面最底部的方格图是什么？**
「写作记录」热力图。一年一行，一格是一周，颜色越深说明那周写得多。它完全由文章日期自动算出来，不需要你填任何东西。

**能在手机上写吗？**
可以先在手机备忘录里写，回到电脑再贴进 `.md` 文件发布。直接在 GitHub 网页上改是不行的——网页上改的内容，下次本地发布会覆盖掉。
